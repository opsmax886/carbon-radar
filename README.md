# 碳雷达 · 双碳招投标与资讯每日聚合系统

一个跑在 GitHub 云端、**每天早自动更新**、**钉钉群自动推送**的双碳信息雷达。
覆盖:碳核查 / 温室气体排放核查、碳足迹 / 碳标签、CCER / 自愿减排、
碳中和规划 / 零碳园区、绿色金融 / ESG、碳市场 / 碳交易。

> 🔰 **不懂编程、用 Mac?** 请直接看 **[新手指南_Mac版.md](新手指南_Mac版.md)** ——
> 手把手写清了每一步点哪里,不需要敲任何命令,约 30 分钟完成。
> 下面这份 README 是给有一点技术基础的人看的简版。

---

## 一、它每天为你做什么

```
北京时间 09:00
   ↓ GitHub Actions 自动唤醒(你无需开机)
抓取 14 个免费公开源(标讯 + 政策 + 方法学 + 动态)
   ↓ 关键词过滤,自动剔除"碳纤维/碳酸钙/碳刷"等噪声
业务匹配度打分(0-100,分数来源可解释)
   ↓ 跨源去重(同一标讯在多个站出现只留一条)
DeepSeek 生成一句话摘要 + 匹配理由
   ↓
钉钉群机器人推送早报  +  网页看板更新
```

**每天你会收到一条钉钉消息**,只包含当天新增的重点标讯和政策,点标题直接跳原文。

## 二、快速部署(约 10 分钟)

### 第 1 步:准备两个密钥

**① DeepSeek API Key(用于生成摘要)**
1. 打开 <https://platform.deepseek.com/> 注册登录
2. 左侧「API keys」→「创建 API key」→ 复制保存(`sk-` 开头)
3. 费用极低,按本系统规模**每月约 1-5 元**,详见文末成本估算

> 没有也可以先跳过:系统会自动降级为"规则打分 + 标题截断",功能照样完整。

**② 钉钉群机器人 Webhook(用于推送)**
1. 打开你要接收消息的钉钉群 → 右上角「群设置」(齿轮图标)
2. 「智能群助手」→「添加机器人」→ 选「自定义(通过 Webhook 接入)」
3. 机器人名称填 `碳雷达`
4. **安全设置勾选「加签」**,复制两样东西:
   - `Webhook` 地址:`https://oapi.dingtalk.com/robot/send?access_token=xxxxx`
   - `密钥`:`SECxxxxx`(点「复制」)
5. 若你更想用「自定义关键词」方式,关键词请填 **碳雷达**(推送标题会带上它)

> 也支持企业微信、飞书,见文末「换个推送渠道」。

### 第 2 步:创建 GitHub 仓库并上传代码

1. 登录 <https://github.com> → 右上角「+」→「New repository」
2. 仓库名填 `carbon-radar`,**可见性二选一**:

| 选择 | 优点 | 代价 |
|---|---|---|
| **Public(公开)** ✅ 推荐新手 | 免费版就能用 GitHub Pages,手机上直接打开看板 | 你聚合的数据别人能看到 |
| **Private(私有)** | 数据不公开 | 免费版**不能**发布 Pages,只能看钉钉推送 + 本地打开网页 |

3. 创建后,把这个 `carbon-radar` 文件夹里的**所有内容**上传上去
   (网页上「Add file」→「Upload files」拖进去,或用 Git 命令)

### 第 3 步:配置密钥

仓库页面 →「Settings」→ 左侧「Secrets and variables」→「Actions」→「New repository secret」,
依次添加:

| Name | Value |
|---|---|
| `DEEPSEEK_API_KEY` | 你的 `sk-xxxxx` |
| `DINGTALK_WEBHOOK` | 钉钉 Webhook 地址 |
| `DINGTALK_SECRET` | 钉钉密钥(`SECxxxxx`) |

> ⚠️ 密钥只存在 GitHub 加密区,不会写进代码,也不会出现在日志里。

### 第 4 步:启用 Actions

仓库页面 →「Actions」选项卡 → 若看到提示就点「I understand my workflows, go ahead and enable them」
→ 左侧选「碳雷达每日更新」→ 右侧「Run workflow」→ 绿色按钮**手动跑一次**

等 1-2 分钟,你应该会:
- 收到**钉钉推送**
- 在仓库里看到 `web/data.js`、`data/history/` 等文件被自动提交

### 第 5 步:打开网页看板

**公开仓库用户:**
「Settings」→ 左侧「Pages」→ Source 选 **GitHub Actions** → 保存。
等 Actions 再跑一次后,访问:

```
https://你的用户名.github.io/carbon-radar/
```

建议把这个地址**添加到手机主屏幕**,随时可看。

**私有仓库用户:**
钉钉推送里已经有当天全部重点内容。要看完整看板时:
1. 在电脑上 `git clone` 或下载仓库
2. **直接双击** `web/index.html` —— 无需服务器、无需联网即可打开
   (这是我把数据同时输出成 `data.js` 的原因:绕开浏览器对 `file://` 的限制)

## 三、每天怎么用

| 你想做的事 | 怎么做 |
|---|---|
| 看今天有什么可投的标 | 钉钉推送里的「🎯 重点标讯」;或网页「招投标」标签 |
| 只看某个省 | 网页「全部地区」下拉选省份 —— 列表按地区分组 |
| 只看某个业务线 | 网页「全部业务线」下拉,如只看「碳核查」 |
| 排除旧信息 | 勾选「只看今日新增」 |
| 搜具体词 | 搜索框输入如 `清单编制`、`零碳园区`、`方法学` |
| 找竞争对手的中标记录 | 搜索框输入公司名;标讯类里"中标公告"会被保留 |

**匹配度分数怎么读**:分数由标题/正文命中的关键词加权算出,鼠标移到卡片上的
「命中:xxx」标签能看到分数来源。`80+` 是明确可投标的项目,`60-79` 是相关线索,
`35-59` 是行业动态。**分数完全可解释,不是黑箱。**

## 四、日常维护(最重要的一节)

### 4.1 调整关键词 —— 系统好不好用,九成靠这个

编辑 `config/keywords.yml`,改完下次运行立即生效,**不需要改代码**。

- **发现漏抓**:把漏掉的说法加进对应业务线的 `keywords`
- **发现噪声**:把噪声词加进 `exclude`
- **某个业务更重要**:把该业务线的 `weight` 调大(如 `1.3`)

### 4.2 看源健康状态

网页顶部的「数据源状态」面板会显示每个源的**最近成功时间、抓到的条数、连续失败次数**。

**务必留意这个告警**:如果某个源"最新内容停在 X 月 X 日",说明它可能已经停更或改版。
这不是系统坏了,而是**数据源本身变了** —— 这类问题如果没人盯着,你会以为"今天没标讯",
实际是"源死了"。本系统实测就抓到过这种情况:

- 碳排放交易网·碳盘查 —— 最新内容停在 2026-07-24
- 生态环境部·新闻发布会 —— 最新内容停在 2026-09-03

### 4.3 源挂了怎么办

| 情况 | 处理方式 |
|---|---|
| 某源连续失败 3 次以上 | 打开 `config/sources.yml`,把该源的 `enabled` 改成 `false` |
| 某个源改版了 | 更新它的 `link_filter` 正则(见 `docs/数据源接入指南.md`) |
| 想加新源 | 在 `config/sources.yml` 里加一段,参考接入指南 |

### 4.4 想改推送时间

编辑 `.github/workflows/daily.yml` 里的 `cron`。

> ⚠️ **GitHub 用的是 UTC 时间!** 换算公式:**UTC = 北京时间 − 8 小时**。
> | 你想的时间(北京) | cron 写法 |
> |---|---|
> | **09:00(当前设置)** | `0 1 * * *` |
> | 07:00 | `0 23 * * *` |
> | 08:30 | `30 0 * * *` |
> | 21:00 | `0 13 * * *` |
>
> 💡 注意:北京时间 00:00–07:59 对应 UTC 前一天 16:00–23:59,
> cron 里的"日"要往前推一天。用 `0 1 * * *`(早上 9 点)这类写法就没有这个坑。

另外 GitHub 的定时任务在高峰期可能延迟几分钟到半小时,属于正常现象。

### 4.5 手动链接池(接微信公众号的官方办法)

**背景**:微信公众号是唯一无法自动接入的来源。实测结论:

| 尝试的路线 | 结果 |
|---|---|
| `profile_ext` 历史文章列表 | ❌ 返回 `{"ret":-3,"errmsg":"no session"}`,必须登录态 |
| 合集 `album` 接口 | ❌ 返回 `ret:10004` |
| 搜狗微信搜索 | ❌ 会话绑定跳转 + JS 反爬,解不出真实链接 |
| RSSHub 公共实例 | ❌ 403 / 503 |
| 搜索引擎收录 / 搜狐等镜像 | ❌ 拿不到该号文章 |
| **单篇文章页** | ✅ **完全公开可读**(标题、公众号名、发布时间、正文都能拿) |

所以办法是:**你把链接贴进来,系统自动补全其余信息。**

**怎么用:**

1. 微信里打开文章 → 右上角「⋯」→「**复制链接**」
2. 打开 `config/manual_links.txt`,在文件末尾新增一行,粘贴链接
3. 保存(网页版 GitHub 点铅笔图标即可编辑)
4. 次日早上 9 点自动抓取,补全标题/公众号名/发布时间,跑关键词打分和 AI 摘要,并入看板和钉钉推送

**规则:**

- 一行一个链接,`#` 开头是注释
- 可在行尾加标签指定归类,不写则**自动识别**(含"招标/采购/申报"→招投标,含"通知/办法"→政策):
  ```
  https://mp.weixin.qq.com/s/xxxxx #tender
  ```
  可用标签: `#tender` `#policy` `#methodology` `#news`
- 抓过的链接记在 `data/manual_cache.json`,**不会重复抓取**(微信文章页有 3MB+,没必要每天重抓)
- 想让同事也能投稿:把该文件在 GitHub 上的链接发给他们,有仓库写权限的就能加

> 💡 这个机制不只支持微信,任何能打开的网页文章链接都能贴进来(靠标准 og 标签提取)。

## 六、常见问题

**Q:为什么中国政府采购网(ccgp)抓不到?**
A:实测它会返回"您的访问过于频繁"的反爬页。不仅是本项目,任何自动化程序都难以稳定直连。
本系统因此改为**聚合碳排放交易网等垂直站的标讯栏目**,绕开反爬。
如果你需要"一条不漏"的覆盖,唯一可靠办法是购买商业标讯 API(剑鱼标讯、千里马等,年费通常几千元),
在 `config/sources.yml` 里按接入指南加一个适配器即可。

**Q:为什么有些源显示"已关闭"?**
A:`config/sources.yml` 里我保留了实测结论,没有把不可用的源伪装成可用:
- 北京绿色交易所 —— 站点显示**"网站维护中"**
- 北极星电力网 —— **阿里云 WAF + 滑块验证码**
- 全国碳市场信息网·行业招标 —— 栏目内容**停留在 2022 年**

这些源一旦恢复,把 `enabled` 改成 `true` 就能重新启用。

**Q:定时任务会不会自己停掉?**
A:GitHub 的定时任务若仓库**连续 60 天无提交**会被自动停用。本系统每天都在提交数据,
所以不会触发。但如果你收到 GitHub 的"workflow disabled"邮件,去 Actions 页面点一次 Enable 即可。

**Q:某天没收到消息,是没标讯还是系统挂了?**
A:不会有这种困惑。当天**没有新增**时,系统会推一条简短的平安消息
(「今日无新增信息,系统运行正常,14 个数据源在线」)。这是刻意设计的:
对监控类工具来说,**沉默是最危险的状态** —— 你无法区分"真没消息"和"脚本已经挂了一个月"。
不想要这条消息的话,把 `config/sources.yml` 里的 `push_heartbeat` 改成 `false`。
同一天多次运行也不会重复推送,只会推送"本次运行新发现"的条目。

**Q:能抓公众号吗?**
A:需要额外中转(如 wechat2rss 自建实例),属于进阶用法,可按接入指南添加 RSS 类型源。

**Q:换个推送渠道?**
A:同时支持企业微信和飞书。在 GitHub Secrets 里加 `WECOM_WEBHOOK` 或 `FEISHU_WEBHOOK` 即可,
系统检测到哪个就推哪个,可以同时推多个。

**Q:数据准不准?**
A:所有内容**只抓标题、链接、日期**,不转载正文,原文以发布站点为准。
日期优先从 URL 提取(最稳定),没有日期的条目标注为"无日期"并排到后面。

## 七、目录结构

```
carbon-radar/
├── config/
│   ├── keywords.yml          ★ 关键词库 + 业务线权重 + 地区表(你最常改的文件)
│   ├── manual_links.txt      ★ 手动链接池:贴微信公众号链接(一行一个)
│   └── sources.yml           ★ 数据源配置(含每个源的实测状态)
├── src/
│   ├── radar.py              抓取 / 解析 / 过滤 / 打分 / 去重 / 源健康监控
│   ├── ai.py                 DeepSeek 摘要与精排(含无 key 时的优雅降级)
│   ├── notify.py             钉钉 / 企业微信 / 飞书推送
│   └── main.py               编排入口
├── web/
│   ├── index.html            ★ 单文件看板(双击即可打开)
│   ├── data.js               自动生成:内嵌数据,供 file:// 打开
│   └── data.json             自动生成:接口数据
├── data/                     自动生成
│   ├── history/              每日历史存档(网页的日期切换靠它)
│   ├── seen.json             去重记忆(识别"今日新增"靠它)
│   └── sources_health.json   源健康状态
├── .github/workflows/daily.yml   ★ 定时任务
└── docs/数据源接入指南.md      ★ 想加新源时看这个
```

**本地手动跑一次**(需要电脑装了 Python 3.9+):

```bash
pip install -r requirements.txt
python src/main.py                 # 完整流程
python src/main.py --no-ai         # 不调 AI,省 token
python src/main.py --no-push       # 只更新数据不推送
python src/main.py --all-sources   # 连已关闭的源也试一遍(排查用)
```

## 八、合规说明

- 仅抓取**公开可访问**的页面,只保存**标题、原文链接、发布日期**
- 同一域名请求间隔至少 3 秒(`config/sources.yml` 的 `request_delay_seconds`)
- 不绕过任何登录、验证码或付费墙;遇到反爬即停止该源并如实标记
- 不转载正文内容,所有条目均链接回原始发布页面
- 建议仅用于个人/团队内部信息参考,商业使用请自行评估各来源的使用条款
