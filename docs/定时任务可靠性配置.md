# 让推送准时到达:外部定时配置

## 为什么要做这件事

GitHub Actions 自带的定时任务(`schedule`)**不保证准时**。GitHub 官方文档明确说明:

> `schedule` 事件在每个整点属于高负载时段,任务可能被延迟几十分钟、**甚至直接丢弃**。

**实测证据**:2026-09-22 把 cron 设为 `0 1 * * *`(北京 09:00),到 09:27 一次都没触发,
历史记录里 `schedule` 触发次数为 **0**。

虽然已经做了两层缓解(避开整点 + 加 10:42 备用时段),但它们仍然是 GitHub 的调度器在跑,
**无法根除风险**。本方案用外部免费定时服务直接调用 GitHub 接口触发,绕开 GitHub 的调度器。

> 💡 **两者可以共存,不会重复推送**。程序用 `data/pushed.json` 记录"哪些条目已成功推送过",
> 同一条目只会被推一次;而且同一天已经推过就不会再发"平安消息"。

---

## 配置步骤(约 10 分钟)

### 第 1 步:创建 GitHub 访问令牌

这个令牌只用于"触发工作流",没有任何其他权限。

1. 浏览器打开 👉 **https://github.com/settings/personal-access-tokens/new**
2. **Token name** 填:`碳雷达定时`
3. **Expiration(有效期)** 选一个较长的(如 1 年)。⚠️ 到期后需要重新生成并更新第 3 步
4. **Repository access** 选「**Only select repositories**」→ 在下拉里选 `carbon-radar`
5. 展开「**Repository permissions**」,找到「**Actions**」,把它设成「**Read and write**」
   - 只需要这一个权限,其他全部保持默认(No access)
6. 拉到最下面点「**Generate token**」
7. 🔴 **页面上会出现一串 `github_pat_` 开头的字符,只显示这一次** —— 立刻复制,存到备忘录

> ⚠️ 这串字符等于进入你仓库的钥匙。**不要发给任何人**,不要截图发群里。

### 第 2 步:注册 cron-job.org

1. 打开 👉 **https://console.cron-job.org/signup**
2. 用邮箱注册 → 去邮箱点验证链接 → 登录

### 第 3 步:创建定时任务

登录后点「**Create cronjob**」,按下面填:

| 字段 | 填什么 |
|---|---|
| **Title** | `碳雷达每日推送` |
| **URL** | `https://api.github.com/repos/opsmax886/carbon-radar/actions/workflows/daily.yml/dispatches` |
| **Execution schedule** | 选「Every day」,时间填 **09:00** |
| **Request method** | 选 **POST** |
| **Request body** | `{"ref":"main"}` |

**⚠️ 时区一定要改!** 在右上角账户设置(或 job 编辑页)里把时区设为 **`Asia/Shanghai`**,
否则它会按服务器时区(通常是 UTC)执行,你就得填 01:00 了。

**然后添加 3 个自定义请求头**(在 Headers 区域):

| Header 名称 | 值 |
|---|---|
| `Authorization` | `Bearer github_pat_你的令牌` |
| `Accept` | `application/vnd.github+json` |
| `Content-Type` | `application/json` |

> `Bearer` 和令牌之间**有一个空格**,别漏掉。

### 第 4 步:测试

点页面上的「**TEST RUN**」按钮。

- ✅ **成功**:显示状态码 **204**(No Content),这是正常的,GitHub 触发成功就是返回 204
- ❌ 显示 401/403:令牌没填对,或权限没给
- ❌ 显示 404:URL 拼错了,或令牌没有选对仓库

测试成功后**记得保存并启用**(Enabled 开关打开)。

## 怎么确认它真的在工作

**在 GitHub 上看运行记录**:

```
https://github.com/opsmax886/carbon-radar/actions
```

点进「碳雷达每日更新」,看每次运行的 **Triggered via** —— 由外部触发的会显示 `workflow_dispatch`。

**在 cron-job.org 上看执行历史**:每个 job 都能看最近 50 次执行的详情、状态码和响应内容。
建议打开「**失败时邮件通知**」,这样它哪天失效你能第一时间知道。

> ⚠️ cron-job.org 有个规则:连续失败 25 次会自动停用该任务。开了邮件通知就不会漏掉。

## 常见问题

**Q:配好之后,GitHub 自带的定时还留着吗?**
A:留着。它是备用 —— 万一 cron-job.org 挂了或令牌过期,GitHub 那边还有机会触发。
两边都触发也不会重复推送(见文首说明)。

**Q:令牌过期了怎么办?**
A:重新做第 1 步生成新令牌,然后到 cron-job.org 编辑那个 job,把 `Authorization` 头里的令牌换成新的。

**Q:能改推送时间吗?**
A:改 cron-job.org 里那个 job 的时间即可,**立即生效**,不用等第二天。
(改 GitHub 那边的 cron 则需要等到下一个周期才生效)

**Q:cron-job.org 安全吗?**
A:令牌存在它的控制台里,它能读取到。所以这个令牌**只给了 Actions 权限、只限这一个仓库**,
即使泄露,最坏后果也只是别人能触发你的数据更新,拿不到代码或账号。
如果你不放心,可以不配外部定时,改用下面的手动方案。

## 备选:完全不依赖第三方(手动触发)

如果哪天没收到推送,去这个页面点一下就行,效果和定时完全一样:

```
https://github.com/opsmax886/carbon-radar/actions
→ 左侧「碳雷达每日更新」→ 右侧「Run workflow」→ 绿色按钮
```

大约 2 分钟跑完,钉钉立刻收到消息。
